How do you work out the time complexity of loops? Easy

Nested loops multiply, sequential blocks add, and you drop constants and lower-order terms (O(3n² + 5n) is O(n²)). A loop variable that is multiplied or divided by a constant gives log n. Watch the geometric-series trap: an inner loop bounded by a doubling i sums to O(n) overall. Hidden costs count too: String += in a loop, list.remove(0) on an ArrayList and substring are each O(n).

How do you find the complexity of recursive code (recurrences and the Master theorem)? Medium

Branching factor b and depth d give roughly O(b^d) calls, which is why backtracking over subsets is O(2ⁿ) and permutations O(n!). Memoisation changes the count to "number of distinct states × work per state", e.g. Fibonacci drops to O(n).

What is the space complexity of recursion? Easy

Interviewers often catch candidates who say "O(1) space" for a recursive solution: each pending call is a stack frame. If depth can be large, convert to an iterative version with an explicit ArrayDeque, or use bottom-up DP. The output itself (e.g. the returned list) is usually not counted as auxiliary space, but say so explicitly.

What is amortized complexity? Give examples. Medium

Amortized means the average cost per operation over a worst-case sequence, not an average over random inputs. It is different from average-case analysis (e.g. HashMap O(1) average assumes a good hash spread). Use the "each element enters and leaves once" argument whenever a nested loop shares a pointer that only moves forward.

Big-O vs Big-Θ vs Big-Ω, and best/average/worst case Easy

In interviews "Big-O" is used loosely to mean the tight worst-case bound, so state which case you mean: "O(n log n) average, O(n²) worst". Also state your variables clearly: a grid is O(R·C), a graph is O(V + E), string problems often depend on both length n and alphabet size k.

Why is HashMap O(1) "on average", and what is its worst case in Java? Medium

Mention that a bad hashCode() (e.g. returning a constant) degrades performance, and that mutable keys break lookups. Choose TreeMap when you need ordering or range queries, and an int[26] array instead of a map for lowercase-letter counts, which is both faster and O(1) space.

How should you approach an unseen coding problem in the interview? Easy

Think aloud the whole way: interviewers grade communication and reasoning, not just a correct final answer. Common optimisations: replace a nested search with a HashMap (O(n²) to O(n)), sort first to enable two pointers or binary search, precompute prefix sums, or cache repeated subproblems.

Spiral Matrix: return all elements in spiral order Medium

Shrink four boundaries after each side. The two if checks stop a single remaining row or column from being added twice. O(R·C) time, O(1) extra space.

Set Matrix Zeroes (in place, O(1) extra space) Medium

Use the first row and first column as marker arrays, with one extra flag for column 0 (because m[0][0] can only mark one of them). The simple version uses two boolean arrays for O(R + C) space. O(R·C) time.

Next Permutation Medium

The suffix after the dip is non-increasing, so swapping in the next larger value and reversing the suffix gives the smallest larger arrangement. If there is no dip, the array is the last permutation and the reverse wraps it to the first. O(n) time, O(1) space.

Maximum Product Subarray Medium

Kadane's variant: track both the largest and the smallest product ending here, because a very negative product becomes the largest after multiplying by a negative. A zero resets both. O(n) time, O(1) space.

First Missing Positive (O(n) time, O(1) space) Hard

The answer is always in 1..n+1, so the array itself can act as the hash set ("index as hash" / cyclic sort). Each swap puts one value in its final slot, so the total work is O(n) despite the inner loop. The same trick solves "find all duplicates" and "find all disappeared numbers".

Range Sum Query with prefix sums (1D and 2D) Easy

O(n) (or O(R·C)) preprocessing, then every query is O(1). The extra leading 0 row/column removes edge cases. If values are updated frequently, a Fenwick tree (Binary Indexed Tree) gives O(log n) for both update and query.

Isomorphic Strings ("egg" ↔ "add") Easy

The mapping must be one-to-one in both directions, so a single map is not enough ("badc" vs "baba"). Recording the last index for each character in both strings checks both directions at once. O(n) time, O(1) space. "Word Pattern" is the same problem with words instead of characters.

Valid Palindrome II (at most one deletion) Easy

On the first mismatch you only need to try deleting the left or the right character once. O(n) time, O(1) space.

Palindromic Substrings: count them all Medium

Same expand-around-centre idea as Longest Palindromic Substring, but count every successful expansion. O(n²) time, O(1) space. Manacher's algorithm does it in O(n), but is rarely expected.

String to Integer (atoi) with overflow handling Medium

The key interview point is detecting overflow before it happens: check res > (MAX - d) / 10 instead of multiplying first. Clamping to MIN_VALUE for negatives works because |MIN| = MAX + 1. O(n) time.

Roman to Integer Easy

A symbol smaller than the one after it is subtracted, otherwise added. O(n). The reverse (Integer to Roman) is greedy: walk a table of values 1000, 900, 500, 400 ... 1 and append each symbol while it fits.

Encode and Decode a List of Strings Medium

Any delimiter alone can appear inside a string, so prefix each string with its length. The decoder reads the length and jumps exactly that far, so # inside the data is harmless. O(total length). This is the same idea as length-prefixed framing in network protocols.

Find a pattern in a text: KMP (strStr) Hard

The naive approach (or String.indexOf) is O(n·m) in the worst case. KMP precomputes the LPS table so that after a mismatch the pattern shifts without re-reading text characters: O(n + m) time, O(m) space. Mention Rabin-Karp (rolling hash) as the alternative for multiple patterns.

Approach

Two pointers, each tracking the max height seen from its side. Always process the side with the smaller max, because the water there is bounded by that max.

Longest Repeating Character Replacement (at most k changes) Medium

A window is valid when length − count of its most frequent char ≤ k. maxFreq never needs to decrease: a smaller value can never produce a longer answer. O(n) time, O(26) space.

Find All Anagrams in a String / Permutation in String Medium

A fixed window of size |p| with letter counts. Comparing two 26-length arrays is O(1), so the total is O(n). You can also keep a "matches" counter to avoid the array comparison.

Minimum Size Subarray Sum (sum ≥ target, positive numbers) Medium

"Shortest valid window": expand right, then shrink left as long as the window stays valid. This only works because all values are positive. With negatives use prefix sums plus a monotonic deque. O(n) time, O(1) space.

Max Consecutive Ones III (flip at most k zeros) Medium

"Longest valid window": the window is valid while it holds at most k zeros. Each index enters and leaves once, so O(n) time and O(1) space.

Longest Substring with At Most K Distinct Characters (Fruit Into Baskets) Medium

The map size is the number of distinct characters in the window. Trick: "exactly K distinct" = atMost(K) − atMost(K−1). O(n) time, O(k) space.

Squares of a Sorted Array (with negatives) Easy

Search Insert Position: the lower-bound template Easy

This one template answers "insert position", "first ≥", "first >", "count of x" and "floor/ceiling". Using a half-open range with lo < hi and hi = mid means the loop always terminates and returns a single index. O(log n).

Search a 2D Matrix (rows sorted, each row starts after the previous ends) Medium

Map a flat index to (mid / C, mid % C) for O(log(R·C)). For the "Search a 2D Matrix II" variant, the staircase walk from the top-right corner eliminates one row or one column per step.

Find Peak Element Medium

Binary search works on unsorted data here because the slope tells you which half must contain a peak (the edges count as −∞). O(log n). This shows that binary search needs a monotonic decision, not necessarily a sorted array.

Single Element in a Sorted Array (every other element appears twice) Medium

Before the single element, pairs start at even indices; after it they start at odd indices. Checking the pair at an even mid tells you which side the break is on. O(log n) versus O(n) for XOR.

Capacity to Ship Packages Within D Days Medium

Binary search on the answer: feasibility is monotonic (a bigger capacity never needs more days). Pick tight bounds, write a greedy feasible(x), and find the smallest feasible x. O(n log(sum)). "Split Array Largest Sum" is the identical code.

Time Based Key-Value Store (get the value at or before a timestamp) Medium

TreeMap.floorEntry is a binary search on a balanced tree, O(log n). If timestamps arrive in increasing order, a plain ArrayList per key with a manual upper-bound search is faster and uses less memory. Know floorKey, ceilingKey, higherKey and lowerKey.

Median of Two Sorted Arrays in O(log(min(m, n))) Hard

Binary search the cut position in the smaller array so that the left halves together hold half the elements and every left value ≤ every right value. Sentinels handle empty sides. O(log(min(m, n))) time, O(1) space. Mention the simpler O(m + n) merge first.

A 0/1 knapsack on booleans: can some subset reach sum/2? Iterating s downwards stops a number from being reused within the same round. O(n · sum) time, O(sum) space. "Target Sum" (+/− signs) reduces to the same subset-sum count.

Coin Change II: number of ways to make the amount Medium

Looping coins in the outer loop counts each combination once ({1,2} and {2,1} are the same). Swapping the loops counts permutations instead (Combination Sum IV). Forward iteration allows unlimited use of each coin, the opposite of 0/1 knapsack. O(n · amount).

Minimum Path Sum in a Grid Medium

dp[r][c] = grid[r][c] + min(top, left), compressed to one row because each cell only needs the row above and the cell to its left. O(R·C) time, O(C) space. This space-optimisation step is a common follow-up for any 2D grid DP.

Longest Palindromic Subsequence Medium

Interval DP: matching ends add 2 to the inside answer, otherwise drop one end. Fill i from the right so the shorter intervals are ready. O(n²) time and space. Equivalent to LCS(s, reverse(s)). "Minimum insertions to make a palindrome" = n − LPS.

Best Time to Buy and Sell Stock with Cooldown (state machine DP) Medium

Model each day as a set of states with transitions. The same template solves all stock variants: unlimited trades (drop the cooldown), with a fee (subtract it on sell), or at most k trades (one hold/sold pair per transaction). O(n) time, O(1) space.

Maximal Square (largest square of 1s) Medium

A square ending at a cell is limited by the smallest square ending at its top, left and top-left neighbours. O(R·C) time. Returning area, not side length, is a frequent slip.

Greedy & Intervals Java

💡 Interval problems almost always start with a sort: by start time to merge or insert, by end time to keep the most non-overlapping ones. For greedy problems, check that a locally best choice can never block a better overall answer. If it can, use DP instead.
Jump Game: can you reach the last index? Medium

Track the farthest index you can reach so far. If the loop ever passes it, you are stuck. O(n) time, O(1) space.

Jump Game II: minimum number of jumps Medium

This is BFS by levels without a queue. Each level is the range you can reach with jumps jumps. O(n) time, O(1) space.

Gas Station: find the starting station for a full circuit Medium

If the total gas is at least the total cost, a solution exists. When the tank goes negative, every station from start to i fails as a starting point, so restart at i + 1. O(n) time, O(1) space.

Merge Intervals Medium

Sort by start. Each interval either extends the last merged interval or starts a new one. O(n log n) time, O(n) for the output.

Insert Interval into a sorted, non-overlapping list Medium

Three phases: copy the intervals before the new one, merge the ones that overlap it, then copy the rest. The input is already sorted, so this runs in O(n).

Non-overlapping Intervals: fewest removals Medium

This is classic activity selection. Keeping the interval that ends earliest leaves the most room for the rest. O(n log n).

Meeting Rooms I: can one person attend every meeting? Easy

After sorting by start, an overlap can only happen between neighbours. O(n log n).

Meeting Rooms II: minimum number of rooms Medium

The heap holds one end time per room in use. Its size at the end is the answer. O(n log n). Another way: sort the starts and ends separately and sweep with two pointers.

Partition Labels Medium

Record the last index of each character. Keep extending the current part's end, and cut when i reaches it. O(n) time, O(1) space.

Assign Cookies and Task Scheduler Medium

Cookies: give each child the smallest cookie that works, O(n log n). Scheduler: the most frequent task sets the frame count. If the other tasks overflow the idle slots, the answer is just tasks.length. O(n).

Best Time to Buy and Sell Stock II (unlimited transactions) Easy

Any rising run's total gain equals the sum of its daily gains, so collecting every positive difference is optimal. O(n) time, O(1) space.

Lemonade Change Easy

Greedy choice: give back the larger bill first, because $5 bills are more flexible for future change. O(n) time, O(1) space.

Minimum Number of Arrows to Burst Balloons Medium

Sort by end and shoot at the earliest end; that arrow pops every balloon starting at or before it. It is the counterpart of Non-overlapping Intervals (answer = n − removals). Integer.compare avoids overflow when values reach ±2³¹. O(n log n).

Boats to Save People (max 2 per boat, weight limit) Medium

The heaviest person must take a boat; pairing them with the lightest is never worse than any other pairing. Sort plus two pointers: O(n log n).

Hand of Straights (split into groups of consecutive cards) Medium

The smallest remaining card can only be the start of a group, which forces the choice. O(n log n) with a TreeMap. Same problem as "Divide Array in Sets of K Consecutive Numbers".

Valid Parenthesis String ('*' can be '(', ')' or empty) Medium

Track the minimum and maximum number of unmatched '(' that are possible. Fail if even the maximum drops below 0; succeed if the minimum can reach 0. O(n) time, O(1) space, much simpler than the DP or two-stack approaches.

Interval List Intersections Medium

Both lists are sorted and disjoint. The overlap of two intervals is [max start, min end]; then advance whichever ends first, because it cannot overlap anything later. O(m + n).

Candy (higher rating than a neighbour gets more candy) Hard

Two passes: left-to-right enforces the rule against the left neighbour, right-to-left against the right one, and max keeps both satisfied. O(n) time, O(n) space. The "two-pass" idea also appears in Trapping Rain Water and Product Except Self.

Tries & Union-Find Java

💡 Use a Trie when a problem asks about many words sharing prefixes, such as autocomplete, wildcard search or searching a board for a whole dictionary. Use Union-Find (DSU) when it asks about connectivity: components, cycle detection in an undirected graph, or grouping by equivalence. With path compression and union by rank, each operation is close to O(1) (amortised O(α(n))).
Implement Trie (insert, search, startsWith) Medium

Every operation is O(L), where L is the length of the word. Space is O(total characters × 26) in the worst case. Use a HashMap<Character, Node> when the alphabet is large.

Design Add and Search Words (with the '.' wildcard) Medium

Ordinary letters follow one branch. A . tries all 26 children. The worst case is O(26^k) for k wildcards, but the search is usually much faster than that.

Word Search II: find every dictionary word in a grid Hard

Put every word in one trie and run a single DFS from each cell. The trie prunes any path that is not a prefix of some word. That is much faster than running Word Search I once per word. Worst case O(R·C·4·3^(L-1)).

Replace Words and Longest Common Prefix with a trie Medium

Replace Words stops at the first node marked as a word end, which is the shortest root. LCP follows the single branch shared by every string. Both run in O(total characters).

Union-Find with path compression and union by rank Medium

Using both optimisations makes find and union amortised O(α(n)), which is effectively constant. Having union return false means the two nodes were already connected, so that edge would form a cycle.

Number of Provinces (connected components) Medium

Start with n components and subtract one for each successful union. O(n² · α(n)). A DFS works just as well.

Redundant Connection: the edge that creates a cycle Medium

The first edge whose endpoints already share a root closes the cycle. O(n · α(n)).

Accounts Merge Medium

Union two accounts whenever they share an email, then group the emails by the root account. O(E log E) because of the sorting, where E is the total number of emails.

Graph Valid Tree Medium

A graph is a tree when it has exactly n−1 edges and no cycle, which together mean it is also connected. O(n · α(n)).

Search Suggestions System (autocomplete: top 3 per typed prefix) Medium

Each node caches its best suggestions, so a lookup is O(prefix length) instead of a DFS over the subtree. That is how real autocomplete trades memory for speed (production systems rank by popularity instead of alphabetically). An alternative without a trie: sort and binary search each prefix.

Maximum XOR of Two Numbers in an Array (binary trie) Medium

Store numbers bit by bit from the most significant bit. To maximise XOR with x, greedily walk to the opposite bit whenever it exists, because a higher bit outweighs all lower bits combined. O(n · 31) time. Inserting x before querying guarantees a path always exists. Assumes non-negative inputs.

Satisfiability of Equality Equations ("a==b", "b!=c") Medium

Equality is an equivalence relation, which is exactly what Union-Find groups. Process all == first, then any != inside one group is a contradiction. O(n · α(26)).

Most Stones Removed with Same Row or Column Medium

Stones sharing a row or column form one component, and every component can be reduced to a single stone, so the answer is stones − components. Treating rows and columns as nodes (instead of stones) avoids comparing all pairs: O(n · α(n)). The key interview insight is recognising the problem as connected components.

Bit Manipulation Java

💡 Cheat sheet: x ^ x = 0, x ^ 0 = x (XOR cancels pairs). x & (x - 1) clears the lowest set bit. x & -x isolates the lowest set bit. (x >> i) & 1 reads bit i. x | (1 << i) sets it and x & ~(1 << i) clears it. In Java, use >>> (unsigned shift) when the input may be negative.
Single Number: every element appears twice except one Easy

XOR is commutative and a ^ a = 0, so only the unpaired value is left. O(n) time, O(1) space.

Number of 1 Bits (Hamming weight) Easy

Brian Kernighan's trick loops once per set bit, not once per bit position. It also works for negative numbers, because the loop ends when n becomes 0.

Counting Bits from 0 to n Easy

This is DP on bits. i >> 1 has already been computed, so the whole table takes O(n).

Reverse Bits of a 32-bit integer Easy

Take the lowest bit off n and add it to res, 32 times. Always O(32).

Power of Two Easy

A power of two has exactly one bit set, so clearing its lowest set bit leaves 0. The n > 0 check excludes 0 and Integer.MIN_VALUE. O(1).

Missing Number in 0..n (XOR) Easy

XOR every index with every value. Each number that is present cancels out, which leaves the missing one. O(n) time, O(1) space, and unlike the sum formula it cannot overflow.

Subsets using a bitmask Medium

Each mask from 0 to 2^n − 1 stands for one subset. O(n · 2^n). This only works for small n (about 20 or fewer).

Sum of Two Integers without + or - Medium

XOR adds without carrying, and AND shifted left gives the carry. Repeat until there is no carry left. Two's complement makes this work for negative numbers too. At most 32 iterations.

Single Number II (every other element appears three times) Medium

XOR alone fails because three copies don't cancel. Count each bit position modulo 3: bits from the triples sum to a multiple of 3. O(32·n) time, O(1) space, and it works for negatives because bit 31 is handled too. The compact "ones/twos" state-machine version also exists but is harder to explain.

Single Number III (two numbers appear once, the rest twice) Medium

XOR of everything gives a ^ b. Any set bit in it separates a from b, so partition by that bit and XOR each group to isolate them. O(n) time, O(1) space.

Hamming Distance and Total Hamming Distance Easy

XOR marks the differing bits and Integer.bitCount counts them. For all pairs, counting per bit position turns O(n²) into O(32·n).

Power of Four Easy

A power of four is a power of two whose single bit sits at an even index; the mask 0x55555555 (binary 0101...) selects those positions. Alternative: power of two and n % 3 == 1. O(1).

Gray Code (successive values differ by one bit) Medium

The i-th Gray code is i ^ (i >> 1). Incrementing i flips a run of trailing bits, and the XOR with the shifted value cancels all but one of those flips. O(2ⁿ). The reflect-and-prefix construction is the alternative explanation.

Reverse Integer (return 0 on 32-bit overflow) Medium

Check for overflow before multiplying. The edge case of exactly MAX/10 cannot overflow here because the last digit of a valid 10-digit int is at most 2. In Java, % and / truncate toward zero, so negatives work without special handling. O(log₁₀ n).

Java bit questions: >> vs >>>, two's complement and shift gotchas Easy

Java has no unsigned int type, so >>> is how you treat an int as unsigned when shifting (e.g. counting bits of a negative number, otherwise while (n != 0) n >>= 1 loops forever). Know the Integer helpers: bitCount, highestOneBit, numberOfTrailingZeros, reverse, toBinaryString.

Math & Number Theory Java

Most "math" problems are really about four habits: keep numbers inside long, take the modulo after every step, replace repeated work with a formula (fast power, nCr, gcd), and use exact integer arithmetic instead of doubles. Learn the toolkit once and the problems become short.

Overflow and the 10⁹+7 rules

int holds about ±2.1×10⁹ and long about ±9.2×10¹⁸. When a problem says "return the answer modulo 10⁹+7", the answer is too large for any primitive type, so you reduce after every operation. 10⁹+7 is chosen because it is prime (so inverses exist), the sum of two residues still fits in an int, and the product of two residues fits in a long.

Fast exponentiation

To compute bⁿ, write n in binary. Square the base once per bit and multiply it into the result whenever the bit is 1. This needs O(log n) multiplications instead of n − 1. The same loop works for doubles (Pow(x, n)), for modular powers, and for matrices (Fibonacci in O(log n) with the matrix [[1,1],[1,0]]). BigInteger.modPow is the built-in version.

GCD and LCM (Euclid)

gcd(a, b) = gcd(b, a % b), ending at gcd(a, 0) = a. It runs in O(log min(a, b)) steps. lcm(a, b) = a / gcd(a, b) * b: divide first so the intermediate value does not overflow. The basic programs are in Java Coding Programs → GCD and LCM. In problems, gcd mostly appears for reducing fractions to a canonical form (see Max Points on a Line below) and for "can these steps reach that value" questions (a·x + b·y can produce exactly the multiples of gcd(a, b)).

Sieve of Eratosthenes

Mark multiples of each prime starting from i * i, because smaller multiples were already marked by smaller primes. It takes O(n log log n) time and O(n) memory. The code is in Java Coding Programs → Prime Number check and Sieve. A useful variant stores the smallest prime factor spf[x] instead of a boolean, so any x ≤ n can then be factorised in O(log x) by repeatedly dividing by spf[x].

Modular inverse (Fermat)

The inverse of b modulo M is the number b⁻¹ with b · b⁻¹ ≡ 1 (mod M). When M is prime and b is not a multiple of M, Fermat's little theorem gives b⁻¹ = b^(M−2) mod M, which is one fast power. So a / b mod M becomes a · b^(M−2) mod M. If M is not prime, use the extended Euclidean algorithm, and an inverse exists only when gcd(b, M) = 1.

nCr: Pascal's rule and factorials with inverses

Two ways to get binomial coefficients C(n, r):

  • Pascal's rule: C(n, r) = C(n−1, r−1) + C(n−1, r). Build a table in O(n·r). It needs only addition, so it works with any modulus, prime or not. Good for n up to a few thousand.
  • Factorials + inverse: C(n, r) = n! / (r! (n−r)!). Precompute factorials and inverse factorials mod a prime in O(n), then answer each query in O(1). The modulus must be prime and larger than n.
  • For one value without a modulus, use the multiplicative form C = C · (n − r + i) / i for i = 1..r. Each partial result is itself a binomial coefficient, so the division is always exact.

Counting principles

Building blocks
  • Product rule: independent choices multiply (k digits from 10 symbols: 10ᵏ).
  • Sum rule: disjoint cases add.
  • Permutations of r from n: n! / (n−r)!. Combinations: C(n, r).
  • Stars and bars: n identical items into k boxes = C(n+k−1, k−1).
Tricks
  • Complement: count the bad cases and subtract from the total.
  • Inclusion–exclusion: |A ∪ B| = |A| + |B| − |A ∩ B|.
  • Pigeonhole: n+1 items in n boxes means some box holds two (why Find the Duplicate Number must have a repeat).
  • Catalan C(2n, n)/(n+1) = 1, 1, 2, 5, 14, 42…: BST shapes, valid parentheses, triangulations.

Geometry basics

Interview geometry is almost always integer geometry. The key tool is the cross product of vectors OA and OB: cross = (ax − ox)(by − oy) − (ay − oy)(bx − ox). Positive means the turn O→A→B is counter-clockwise (left), negative means clockwise (right), and zero means the three points are collinear. |cross| / 2 is the area of triangle OAB. A polygon's area is |Σ (xᵢ·yᵢ₊₁ − xᵢ₊₁·yᵢ)| / 2 (the shoelace formula). Compare squared distances rather than taking square roots, and keep slopes as reduced integer pairs, never as doubles.

Randomized algorithms

  • Reservoir sampling: pick one item uniformly from a stream of unknown length. Keep the i-th item with probability 1/i. For k items, replace a random slot when rnd.nextInt(i) < k.
  • Fisher–Yates shuffle: for i from n−1 down to 1, swap a[i] with a[j] where j is uniform in [0, i]. That gives each of the n! orders equal probability. Collections.shuffle uses this algorithm.
  • Weighted pick: prefix sums plus a binary search for a random target.
  • Rejection sampling: generate in a bigger range and retry outside the wanted one (rand7 → rand10, a random point in a circle).

Interview Questions — Powers, Modulo & Combinatorics

Pow(x, n) with a negative exponent Medium
Approach

Binary exponentiation. Convert n to long first, because -Integer.MIN_VALUE does not fit in an int. For a negative exponent, invert x and make the exponent positive.

Time O(log n), space O(1). The recursive version (half = pow(x, n/2); return half * half * (odd ? x : 1)) is equally fine, but it must not call pow(x, n/2) twice, because that makes it O(n) again.

Count Good Numbers (modular fast power) Medium
Approach

A digit string of length n is "good" when even indices hold an even digit (5 choices: 0, 2, 4, 6, 8) and odd indices hold a prime digit (4 choices: 2, 3, 5, 7). By the product rule the answer is 5^⌈n/2⌉ · 4^⌊n/2⌋. Here n can be as large as 10¹⁵, so the powers must be modular fast powers.

Time O(log n), space O(1). Keep modPow as a reusable helper: the next problem, and every "divide under a modulus" question, needs it.

nCr mod 10⁹+7 for many queries (factorials and Fermat inverse) Medium
Approach

Precompute fact[i] = i! mod M. Compute the inverse of the largest factorial once with Fermat, then walk downwards using inv[i−1] = inv[i] · i, because 1/(i−1)! = i / i!. Each query is then two multiplications.

Time O(n + log M) to build, then O(1) per query. Space O(n). Note the order fact[n] * invFact[r] % MOD * invFact[n-r] % MOD: reduce after each multiplication, or the product of three residues overflows a long.

Unique Paths in a grid, solved with nCr instead of DP Medium
Approach

Every path from the top-left to the bottom-right has exactly m−1 down moves and n−1 right moves, in some order. Choosing which positions are the down moves gives C(m+n−2, m−1). The DP table version is in the Dynamic Programming chapter. This one is O(min(m, n)) time and O(1) space.

Time O(min(m, n)), space O(1). Multiply before dividing. Dividing first (res * ((total-k+i) / i)) truncates and gives wrong answers. Unique Paths II (with obstacles) cannot use this formula, so it stays a DP.

Pascal's Triangle and Pascal's Triangle II (one row in O(k) space) Easy
Approach

Each inner entry is the sum of the two entries above it. For a single row, update one array from right to left, so that row[c-1] still holds the previous row's value when you read it.

Time O(n²) for the triangle and O(k²) for one row. Space O(k) for one row. Going left to right would add the new value of row[c-1] and produce the wrong numbers.

Factorial Trailing Zeroes Medium
Approach

A trailing zero comes from a factor 10 = 2 × 5. There are always more 2s than 5s in n!, so count the 5s: multiples of 5 give one each, multiples of 25 give one more, multiples of 125 one more, and so on.

Time O(log₅ n), space O(1). Computing n! and counting zeros overflows even a long at 21!, so the formula is the only practical way.

Interview Questions — Number Puzzles

Ugly Number II (the n-th number whose only prime factors are 2, 3, 5) Medium
Approach

Every ugly number is a smaller ugly number times 2, 3 or 5. Keep three pointers into the sequence built so far and take the smallest of the three candidates each step. Advance every pointer that produced that value, so duplicates such as 6 = 2·3 = 3·2 appear only once.

Time O(n), space O(n). A min-heap with a seen-set also works in O(n log n). The three-pointer merge is the expected answer.

Happy Number Easy
Approach

Repeatedly replace n by the sum of the squares of its digits. The sequence either reaches 1 or falls into a cycle. Detect the cycle with Floyd's slow and fast pointers, the same technique as Linked List Cycle, so no extra set is needed.

Time O(log n) per step, and the values quickly drop below 243 (the most a 3-digit number can produce), so the loop is short. Space O(1). A HashSet of seen values is the simpler alternative.

Excel Sheet Column Title and Column Number Easy
Approach

This is base 26 with digits 1..26 instead of 0..25 (there is no zero digit). Subtract 1 before each % 26 to shift to 0-based. Going the other way is ordinary base conversion.

Time O(log₂₆ n), space O(1). Forgetting the n-- maps 26 to "A@" instead of "Z", which is the classic bug.

Multiply Strings (no BigInteger) Medium
Approach

Grade-school multiplication. Digit i of a times digit j of b lands at positions i + j (carry) and i + j + 1 (units) of an array of length m + n. Process from the right so carries move left.

Time O(m·n), space O(m + n). The product of an m-digit and an n-digit number has at most m + n digits, which is why the array is that long.

Fraction to Recurring Decimal Medium
Approach

Long division. The digits start repeating exactly when a remainder repeats, so map each remainder to the position where its digit was written. When you see it again, insert "(" at that position. Use long because Math.abs(Integer.MIN_VALUE) is still negative as an int.

Time O(den) in the worst case, because there are at most den different remainders. Space O(den). Edge cases interviewers check: zero numerator, a negative result, and -2147483648 / -1.

Interview Questions — Geometry & Randomized

Orientation test with the cross product (Valid Boomerang) Easy
Approach

Three points form a "boomerang" (a real triangle) when they are not collinear. The cross product is 0 exactly when they are collinear, including when two of them coincide. It is pure integer arithmetic, so there are no slopes, no division and no doubles.

Time O(1), space O(1). The same function is the core of convex hull (Andrew's monotone chain pops points while the turn is not a left turn), of segment intersection tests, and of triangle area (Math.abs(cross) / 2.0).

Max Points on a Line Hard
Approach

Fix each point as an anchor and group the other points by their slope from it. Store the slope as a reduced pair (dy/g, dx/g) with one sign convention, not as a double: doubles lose precision, and vertical lines would need a special case. The biggest group plus the anchor itself is a candidate.

Time O(n² log C) where C is the coordinate range (for the gcd). Space O(n). Only points after i need checking: any line through i and an earlier point was already counted when that earlier point was the anchor. A long key such as dx * 100_000L + dy avoids building strings.

Random Pick with Weight Medium
Approach

Lay the weights end to end on a number line using prefix sums. Draw a uniform integer in [1, total] and binary search for the first prefix sum that is ≥ it. Index i owns a stretch of length w[i], so it is picked with probability w[i] / total.

Time O(n) to build, O(log n) per pick. Space O(n). The off-by-one is the trap: with nextInt(total) (0-based) you must search for the first prefix sum strictly greater than the target.

Linked List Random Node (reservoir sampling) Medium
Approach

Walk the list once. When you are at the i-th node, keep it as the answer with probability 1/i. You never need the length in advance, so this works for a stream too. For node k, P(chosen and never replaced) = (1/k) · (k/(k+1)) · … · ((n−1)/n) = 1/n.

Time O(n) per call, space O(1). If the list never changes and calls are frequent, copying it into an ArrayList once gives O(1) picks, at the cost of O(n) memory. Name that trade-off in the interview.

Shuffle an Array (Fisher–Yates) Medium
Approach

Go from the last index down to 1 and swap each position with a uniformly random index in [0, i], inclusive. Every permutation then comes out with probability exactly 1/n!. Keep a copy of the original for reset.

Time O(n), space O(n) for the copy. Using nextInt(i) instead of nextInt(i + 1) is Sattolo's algorithm, which only produces single-cycle permutations, so it is a different (and here wrong) shuffle.

Fenwick tree: why i & -i

A Fenwick tree is an array t[1..n] where t[i] stores the sum of the last lowbit(i) elements ending at i, that is a[i − lowbit(i) + 1 .. i], with lowbit(i) = i & -i. In two's complement, -i = ~i + 1, so i & -i keeps only the lowest set bit (see the Bit Manipulation cheat sheet).

  • Prefix query: add t[i], then jump to i -= i & -i. Each step removes one set bit, so there are at most log n steps.
  • Update: add to t[i], then jump to i += i & -i, the next range that also covers i.
  • It is 1-indexed because lowbit(0) = 0, so index 0 would loop forever.
  • A range sum is prefix(r) − prefix(l − 1), which is why the operation must be invertible. A Fenwick tree cannot answer range minimum in general.

Segment tree: build, query, update, lazy propagation

Node 1 covers [0, n−1]. A node covering [l, r] has children 2·node for [l, mid] and 2·node+1 for [mid+1, r]. An array of size 4n is always enough. A query has three cases: no overlap (return the identity, such as 0 for sum or +∞ for min), full overlap (return the stored value), and partial overlap (ask both children and combine). A range query visits O(log n) nodes, at most four per level.

Lazy propagation makes range updates O(log n) too. Instead of visiting every leaf in the range, stop at fully covered nodes, update their aggregate directly, and leave a pending tag ("add 3 to everything below"). Push the tag down to the children only when a later operation needs to go below that node. For each tag you must define two things: how it changes a node's aggregate (add v to a sum: sum += v · length; assign v: sum = v · length), and how two tags combine (adds add up, a later assign replaces earlier tags).

Sparse table (static range min/max)

Precompute st[k][i] = min of the block of length 2ᵏ starting at i. Any range [l, r] is covered by two blocks of length 2ᵏ with k = ⌊log₂(r − l + 1)⌋, one starting at l and one ending at r. They overlap, which is fine for min, max and gcd (applying them twice changes nothing) but not for sum. It is O(n log n) to build and O(1) per query, with no updates allowed. It is mostly used for LCA and for read-only range-minimum queries.

Cache design: LRU and LFU

LRU is already covered: the HashMap plus doubly linked list version is in Linked List → LRU Cache, and the LinkedHashMap(accessOrder = true) plus removeEldestEntry version is in the Java guide's Collections chapter. LFU evicts the key with the lowest use count, and breaks ties by evicting the least recently used of those keys. The O(1) design keeps three maps: key → value, key → count, and count → keys in insertion order (LinkedHashSet), plus a minFreq variable. minFreq only changes in two ways: it resets to 1 when a new key is inserted, and it goes up by one when the last key leaves the minFreq bucket.

Interview Questions — Fenwick & Segment Trees

Range Sum Query – Mutable (Fenwick tree) Medium
Approach

Keep a 1-indexed Fenwick tree over the values and a copy of the array. An update adds the difference between the new and the old value. A range sum is the difference of two prefix sums.

Time O(n log n) build, O(log n) per update and per query. Space O(n). An O(n) build: copy the values into tree, then for each i add tree[i] to tree[i + (i & -i)] if that index exists.

Range Sum Query – Mutable (recursive segment tree template) Medium
Approach

The same problem with a segment tree. This is the template to memorise, because swapping + for Math.min, Math.max or gcd (and 0 for the matching identity) answers other range questions, which a Fenwick tree cannot do.

Time O(n) build, O(log n) per update and query. Space O(4n). The 4n bound comes from the tree height ⌈log₂ n⌉ + 1: the last level can need up to 2·2^⌈log₂ n⌉ < 4n slots.

Range add and range sum with lazy propagation Hard
Approach

Store sum[node] and a pending lazy[node] add. Applying v to a node adds v · length to its sum and adds v to its tag. Before descending into a node's children, push its tag down. Fully covered nodes stop the recursion, which keeps both operations O(log n).

Time O(log n) per operation, space O(4n). push is never called on a leaf, because a leaf is always either fully inside or fully outside the range, so 2 * node stays within bounds. For "assign v to a range", change apply to sum = v · length and make the tag overwrite instead of add, using a separate flag for "no tag".

Range Minimum Query on a static array (sparse table) Medium
Approach

Build blocks of length 1, 2, 4, 8… from the previous level. Answer [l, r] with two overlapping blocks of length 2ᵏ that together cover the range exactly.

Time O(n log n) build, O(1) per query. Space O(n log n). If the array changes, use a segment tree instead. The table cannot be updated cheaply.

Count of Smaller Numbers After Self Hard
Approach

Scan from the right. Keep a Fenwick tree that counts how many of the values seen so far have each rank. For nums[i], the answer is the count of ranks strictly below its own, and then you add it to the tree. Coordinate-compress the values to ranks 1..m first, because they can be negative or large.

Time O(n log n), space O(n). It is the per-element version of Count Inversions (Sorting chapter). Merge sort that tracks original indices also solves it in O(n log n). The same Fenwick pattern solves Reverse Pairs and Count of Range Sum.

Falling Squares (coordinate compression + segment tree with range assign) Hard
Approach

A square with left edge x and side s covers the integer cells x .. x+s−1 and lands on the tallest block in that range, so its top is max(range) + s. Then the whole range is set to that height. Compress the cell endpoints and use a segment tree with range max query and range assign. The new height is larger than everything in the range, so "assign" is safe.

Time O(n log n), space O(n). Using the inclusive right cell x + s − 1 is what makes squares that only touch at an edge not overlap. With n ≤ 1000, the O(n²) solution (compare each square with every earlier one) is also accepted. Mention it first, then offer the tree.

Interview Questions — Cache & Design

LFU Cache with O(1) get and put Hard
Approach

Three maps: key → value, key → use count, and count → keys in order of last use (LinkedHashSet gives O(1) removal and remembers order). Track minFreq. To evict, take the first (oldest) key in the minFreq bucket. A new key always has count 1, so minFreq becomes 1 on every insert.

Time O(1) for both operations, space O(capacity). The usual bugs are forgetting the LRU tie-break, which is why a plain HashSet is wrong, and recomputing minFreq by scanning, which is O(n).

Design Hit Counter (hits in the last 300 seconds) Medium
Approach

Use a circular buffer of 300 slots indexed by timestamp % 300. Each slot stores the timestamp it was last used for and the hits at that time. If a slot holds an old timestamp, it belongs to an earlier window, so reset it.

Time O(1) per hit and O(300) per query, space O(300) however many hits arrive. A Queue<Integer> of timestamps (poll while older than t − 299) is simpler but stores every hit. The follow-up "what if there are millions of hits per second" points to the buffer. For concurrent use, wrap the methods in a lock or use AtomicIntegerArray with care, because the check-then-reset is not atomic.

My Calendar I (no double booking) Medium
Approach

Keep the bookings in a TreeMap from start to end, with half-open intervals [start, end). A new event only has to be checked against its two neighbours: the booking that starts at or before it, and the one that starts after it.

Time O(log n) per booking, space O(n). Two intervals [a, b) and [c, d) overlap exactly when a < d && c < b. A plain list with that check is the O(n) version.

My Calendar II (no triple booking), with the sweep version for My Calendar III Medium
Approach

Keep two lists: all bookings, and the regions that are already double-booked. A new event fails if it hits any double-booked region. Otherwise, add its overlap with every existing booking to the double-booked list. The general alternative is a difference map: +1 at each start, −1 at each end, then sweep in key order and track the running count.

Time O(n) per booking for both, space O(n). The sweep generalises to "at most k overlaps" and to Meeting Rooms II (the maximum running count is the number of rooms). With very many bookings, a dynamic segment tree with range add and range max makes each booking O(log C).

Range Module (add, remove and query half-open ranges) Hard
Approach

Store disjoint, merged intervals in a TreeMap from start to end. Add: extend the new range to swallow the interval touching its left side and the one overlapping its right side, then delete every interval that starts inside it. Remove: split off the parts that stick out on the left and right, then delete what starts inside. Query: a single interval must cover the whole range, because touching intervals are always merged.

Time O(log n) per query and amortised O(log n) per add or remove, because each interval is inserted once and deleted at most once. Space O(n). In removeRange, handle the right side before the left side: if one interval covers both ends, cutting the left first would lose the tail.

Snapshot Array (versioned reads) Medium
Approach

Don't copy the array on snap(). Each index keeps a TreeMap from snap id to the value set during that snap. A read at snap s is the floor entry of s. This is the same idea as Time Based Key-Value Store in the Binary Search chapter.

Time O(log s) for set and get, O(1) for snap. Space O(length + number of sets). Copying the whole array per snap costs O(length) for every snap, which is the naive answer interviewers want you to improve on.

Sorting Algorithms Java

Bubble Sort (with early exit) Easy

O(n log n) in every case / O(n) space

Quick Sort (Lomuto partition) Medium

Average O(n log n), worst case O(n²) on already-sorted input with a last-element pivot. Use a random pivot to avoid that. It sorts in place.

Heap Sort (in place, O(n log n) worst case) Medium

Build a max-heap bottom-up, then repeatedly swap the root to the end and shrink the heap. O(n log n) in every case and O(1) extra space, but not stable and cache-unfriendly, so quick sort is usually faster in practice. Introsort (C++ std::sort) falls back to heap sort when quick sort recursion gets too deep.

Counting Sort (small integer range) Easy

No comparisons, so it beats the Ω(n log n) comparison bound: O(n + k) time and O(n + k) space, where k is the value range. Use it only when k is not much bigger than n. The prefix-sum + backwards pass keeps it stable, which radix sort depends on.

Radix Sort (LSD, non-negative integers) Medium

Sort by the least significant digit first, using a stable counting sort each pass. O(d · (n + b)) for d digits in base b, effectively linear for fixed-width keys. Negatives need separate handling (or an offset). Bucket sort is the related idea for uniformly distributed floats: O(n) average.

Quick Sort with a random pivot and Hoare partition Medium

A random pivot makes the O(n²) worst case (sorted input with a fixed pivot) extremely unlikely. Hoare does about three times fewer swaps than Lomuto and handles many duplicates better. For heavy duplicates, use 3-way partitioning (Dutch National Flag). Recursing into the smaller side first bounds the stack at O(log n).

Quickselect: Kth largest element in O(n) average Medium

Like quick sort, but only continue into the side that contains the target index: n + n/2 + n/4 + ... = O(n) average, O(n²) worst. Compare with a size-k heap (O(n log k), better for streams) and full sorting (O(n log n)).

Count Inversions (pairs i < j with a[i] > a[j]) using merge sort Hard

When a right-half element is placed before remaining left-half elements, it forms an inversion with every one of them. O(n log n) instead of O(n²). It measures how "unsorted" an array is; the same trick solves "Reverse Pairs" and "Count of Smaller Numbers After Self".

Largest Number (sort with a custom comparator) Medium

The order is defined by which concatenation is larger, not by numeric value ("3" before "30" because 330 > 303). A comparator must be consistent (transitive), which this one is. O(n log n · L). Related Java points: Comparator.comparing(...).thenComparing(...), Integer.compare instead of subtraction (overflow), and the fact that Arrays.sort on objects is stable (TimSort).

Semaphore: allow at most 3 concurrent calls to a slow API Medium

A semaphore holds a number of permits; acquire blocks until one is free. Thread-safe word count with ConcurrentHashMap (and the check-then-act bug) Medium

Each single method call on a ConcurrentHashMap is thread-safe, but a sequence of calls is not. merge, compute and computeIfAbsent lock only that key's bin, so other keys are not blocked. Keep the lambdas short and never modify the same map from inside them. ConcurrentHashMap does not allow null keys or values, because a null from get would be ambiguous.

Read-mostly cache with ReentrantReadWriteLock Medium

Read locks are shared and the write lock is exclusive, so throughput improves when reads far outnumber writes. You can downgrade (take the read lock while holding the write lock, then release the write lock), but you cannot upgrade a read lock to a write lock; trying to do so deadlocks. In real code a ConcurrentHashMap or Caffeine cache is usually the better answer; mention StampedLock for optimistic reads.

Java 21 virtual threads: run 10,000 blocking calls Easy

Virtual threads are cheap JVM-managed threads mounted on a small pool of carrier threads; when one blocks on I/O, it unmounts and the carrier runs another. Use them for many blocking, I/O-bound tasks (one thread per request); they do not make CPU-bound work faster. Don't pool them, and limit access to scarce resources with a Semaphore. Before Java 24, blocking inside synchronized could pin the carrier thread, so ReentrantLock was preferred around long blocking calls. In Spring Boot 3.2+, spring.threads.virtual.enabled=true switches request handling to virtual threads.

CompletableFuture error handling in depth: handle vs exceptionally, completeOnTimeout, anyOf Medium

exceptionally runs only on failure, handle always runs and can transform both outcomes, and whenComplete observes without changing the result. The exception arrives wrapped in a CompletionException, so check ex.getCause(). Always pass your own executor for blocking I/O; the default common ForkJoinPool is sized for CPU work. join() throws unchecked exceptions, while get() throws checked ones.

mappedBy marks Order.items as the inverse side, so the FK is managed by OrderItem.order. cascade = ALL saves and deletes items along with their order. orphanRemoval deletes an item from the database when it is removed from the list. Derived query methods Easy

JPQL works with entity and field names and is portable across databases. Native queries use table and column names and can use features specific to one database. Bulk updates need @Modifying and skip the persistence context, which is why the code clears it.

Projections: interface-based and DTO constructor queries Medium

Projections fetch fewer columns and return read-only objects that are never managed or dirty-checked, so they are cheaper. A constructor expression needs the fully qualified class name. Spring Data 3 can also map a JPQL tuple into a record directly.

Fixing N+1 with JOIN FETCH or @EntityGraph Hard

Don't use JOIN FETCH on a collection together with pagination. Hibernate then pages in memory and logs warning HHH90003004. In that case, fetch a page of IDs first, then fetch those orders with their items. You can't JOIN FETCH two List bags at once (MultipleBagFetchException), so use a Set or separate queries.

Page runs an extra COUNT query, and Slice doesn't. Give a custom countQuery for complex joins. On very large tables, use keyset (seek) pagination such as where id > :lastId instead of large offsets.

Optimistic locking with @Version Medium

When another transaction has already changed the row, the update matches 0 rows and Spring throws ObjectOptimisticLockingFailureException. Retry it or return 409 Conflict. @Retryable comes from spring-retry and needs @EnableRetry. Optimistic locking fits when conflicts are rare. Pessimistic locking fits hot rows.

Auditing with @CreatedDate, @LastModifiedDate and @CreatedBy Easy

Specifications for dynamic filters Hard

Specifications wrap the Criteria API in small predicates you can combine. That fits search screens with optional filters, so you don't need a separate query method for every combination. Batch insert tips Medium

Hibernate can't batch inserts for IDENTITY IDs, because it needs each generated key straight away. Use a SEQUENCE with a pooled allocation size, or JdbcTemplate.batchUpdate. Flushing and clearing every N rows keeps the persistence context from growing without limit.

LazyInitializationException: why it happens and how to fix it Medium

Create the right index and read EXPLAIN Medium

Composite index rule: put equality columns first, then the range or sort column, and follow the leftmost prefix. (customer_id, order_date) serves WHERE customer_id=? on its own, but not WHERE order_date=? on its own.

Query order of execution (why you can't use an alias in WHERE) Easy

SELECT aliases are created after WHERE runs, so WHERE can't see them. ORDER BY can use them, and MySQL also lets HAVING use them. To filter on a window function's result, wrap the query in a subquery or CTE.

Employees who earn the same salary as someone else Easy

The a.id < b.id condition is the standard trick in self joins: it removes both self-matches (a = a) and mirrored pairs (A,B and B,A). The window version keeps every column of the matching rows without a second scan of the table.

Find missing ids (gaps) in a sequence Medium

The LEAD version is a single pass and returns compact ranges, so it scales to large tables. The generated sequence lists each missing value but needs a number source; raise cte_max_recursion_depth for big ranges. The same "generate then anti-join" idea fills in missing dates in a daily report so days with zero sales still show up.

FIRST_VALUE, LAST_VALUE and NTH_VALUE (and the default frame trap) Medium

When a window has ORDER BY, the default frame is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW, so LAST_VALUE only sees rows up to the current one (and its peers with the same salary). Specify the full frame to get the true last value. The named WINDOW clause (MySQL 8) avoids repeating the same OVER (...) definition.

Subtotals and a grand total with WITH ROLLUP and GROUPING() Medium

WITH ROLLUP adds a subtotal row for each level of the GROUP BY list (right to left) plus a grand total, with NULL in the rolled-up columns. GROUPING(col) (MySQL 8.0.1+) returns 1 on those generated rows, which separates them from real NULL data; that's better than COALESCE. This replaces a UNION ALL of several aggregate queries.

Repeat customers, and month-over-month retention Medium

Reduce orders to one row per customer per month first (DISTINCT), then self-join each month to the following month. The LEFT JOIN keeps customers who did not come back, so COUNT(b.customer_id) counts only the retained ones. In MySQL a boolean expression is 0 or 1, so SUM(condition) counts matching rows (portable form: SUM(CASE WHEN ... THEN 1 ELSE 0 END)).

Create a view (and when it can be updated) Easy

A view is a stored, named query: it stores no data (MySQL has no materialised views), and runs the underlying query each time. Uses: hide complex joins, expose only some columns for security (grant access to the view, not the table), and keep a stable interface while tables change. Views with aggregates, DISTINCT, GROUP BY or UNION are read-only.

Stored procedure with a transaction, and an audit trigger Medium

DELIMITER is a client command that lets the body contain semicolons. A procedure can have IN, OUT and INOUT parameters and run several statements as one unit; a trigger runs automatically for each affected row, with OLD and NEW row values. In a Spring application most business logic belongs in Java (testable, versioned, portable), so procedures are used for heavy set-based jobs and triggers for audit or integrity rules. Call a procedure from Spring Data JPA with @Procedure.

Query a JSON column (->>, JSON_CONTAINS, JSON_TABLE, indexing) Medium

JSON columns are validated on insert and stored in a binary format. Use them for genuinely flexible attributes (user preferences, form answers, FHIR-style extensions); keep fields you filter or join on as normal columns. A JSON path can't be indexed directly, so index a generated column (or, for arrays, a multi-valued index with CAST(... AS ... ARRAY)).

MongoDB Query Questions MongoDB

💡 The examples use orders { _id, customerId, status, amount, items: [{ sku, qty, price }], tags: [], createdAt } and customers { _id, name, city }. Stage order matters in a pipeline: $match early so it can use an index, then $group, $sort, $project. For indexes, follow the ESR rule: Equality fields first, then Sort fields, then Range fields.
Find with comparison and logical operators Easy

Conditions listed together in one filter are joined with an implicit AND. Use $elemMatch when several conditions must hold for the same array element. Without it, {"items.sku": "P100", "items.qty": {$gte: 2}} can be satisfied by two different elements.

Projection, sorting, skip and limit Easy

A projection either includes fields (1) or excludes them (0). You can't mix the two, except for excluding _id. A large skip is slow because the skipped documents are still scanned, so use range-based paging such as {_id: {$gt: lastId}} instead.

Update operators: $set, $inc, $push, $addToSet, $pull and upsert Medium

$push always appends, while $addToSet appends only if the value isn't already there. Updates to a single document are atomic. Use findOneAndUpdate(..., {returnDocument: "after"}) to get back the updated document.

Aggregation: total amount and order count per customer Medium

Equivalent SQL: SELECT customerId, SUM(amount) ... WHERE status='shipped' GROUP BY customerId HAVING SUM(amount) > 1000 ORDER BY 2 DESC. A $match placed after $group plays the role of HAVING.

Top N per group: the 2 biggest orders for each customer Hard

$topN and $bottomN keep only N items in memory for each group. The push-and-slice version builds a full array for each group first, which can hit the 16 MB document limit. $setWindowFields is the MongoDB version of SQL's ROW_NUMBER()/RANK() OVER (PARTITION BY ...).

$lookup join: orders with customer details Medium

$lookup works like a LEFT OUTER JOIN and always produces an array. Add $unwind to get inner-join behaviour, or use preserveNullAndEmptyArrays: true to keep a left join. Index the foreign field (orders.customerId) for speed.

$unwind: best-selling SKUs across all order items Medium

$unwind turns an array into one document per element, so it's the usual step before grouping on array contents. Documents with a missing or empty array are dropped unless you set preserveNullAndEmptyArrays.

Group by date: monthly revenue for 2025 Medium

Filter by date range first so the index on createdAt can be used. Dates are stored in UTC, so pass a timezone to get local calendar buckets.

Text search Medium

A collection can have only one text index, though it can cover several fields. It does stemming and removes stop words. For fuzzy matching, autocomplete or facets, Atlas Search ($search, built on Lucene) is the production choice.

Creating indexes and reading explain() Hard

A compound index also serves queries on its prefixes, so {status, createdAt} works for status alone but not for createdAt alone. A covered query, where the filter and the projected fields are all in the index and _id is excluded, never reads the documents. Every index slows down writes, so only add the ones your queries actually use.

Update elements inside an array: $, $[] and arrayFilters Medium

The positional $ updates only the first element matched by the query, which surprises people when several elements match. $[] touches all elements and $[identifier] with arrayFilters touches only the elements that pass the filter. All of these are atomic within a single document.

Paginated results plus total count in one query ($facet) Medium

$facet runs several sub-pipelines over the same input and returns one document, so a list page gets its rows, the total and the filter counts in a single round trip. The whole result must fit in the 16 MB document limit, and the stages inside a facet can't use indexes, so put $match and $sort before it. For deep pages, range-based paging on _id or createdAt is faster than $skip.

Group orders into amount ranges ($bucket) Medium

$bucket is the aggregation equivalent of SQL's CASE WHEN amount < 500 ... followed by GROUP BY. Boundaries must be sorted, each bucket includes its lower bound and excludes its upper bound, and any value outside the boundaries goes to default (without a default, such documents make the stage fail).

Data-quality queries: missing fields, wrong types, array sizes, distinct values Easy

Because MongoDB is schema-flexible, these checks are common when cleaning or migrating data. $size only matches an exact length; for "greater than" use the array-index trick or $expr. { field: null } matches both null and missing, while $exists distinguishes them. An update with a pipeline (an array) can compute new values from existing fields.

Computed fields with $addFields, $cond and $switch Easy

$addFields (alias $set) keeps all existing fields and adds new ones, while $project reshapes the document. $cond is a ternary, $switch is a CASE expression, and $map/$filter/$reduce work on arrays inside a document without unwinding it. $$i refers to a variable, and $field to a field path.

Multi-document transaction: transfer money between wallets Hard

A single-document update is always atomic, so a good schema (embedding data that changes together) avoids most transactions. When several documents or collections must change together, use a session transaction; it needs a replica set, has a default 60-second limit, and costs more than single-document writes. In Spring, MongoTransactionManager lets you use @Transactional. Drivers retry on TransientTransactionError, so keep the transaction logic idempotent.

bulkWrite: many inserts, updates and deletes in one round trip Medium

Batching avoids one network round trip per document, which matters a lot for imports and sync jobs. With ordered: true (the default) MongoDB stops at the first error; with ordered: false it attempts every operation, may run them in parallel, and reports all errors at the end. A bulk write is not a transaction: earlier operations stay applied even if a later one fails.

Enforce a schema with $jsonSchema validation Medium

Flexible schema doesn't have to mean no schema. Server-side validation rejects bad writes from any client (scripts, other services), not only from your app. Use validationAction: "warn" to introduce rules on an existing collection safely, then switch to "error". Application-level validation (Bean Validation on your Java documents) still gives better error messages to users.

Spring Data MongoDB mirrors Spring Data JPA: derived queries from method names, @Query with a JSON filter (plus projection), and @Aggregation for pipelines whose result is mapped to a record (the group's _id maps to id). Use MongoTemplate with Criteria for dynamic queries or complex updates, and @Indexed/@CompoundIndex on the document class to declare indexes. Constructor promotion declares and assigns properties in a single step. readonly (8.1) properties can only be set once, during initialisation. Program to the Shape interface so new shapes can be added without changing the loop, which is the open/closed principle.

JSON API endpoint with json_encode Medium

Set the content type, return the right status codes, and read the POST body from php://input. JSON_THROW_ON_ERROR throws instead of quietly returning null. The never return type (8.1) tells PHP that respond always exits.

Recursion: factorial and Fibonacci (with memoization) Easy

Plain recursive Fibonacci takes O(2^n). Memoising it with the array passed by reference brings it down to O(n). PHP doesn't optimise tail calls, so very deep recursion can hit memory or stack limits. Prefer the iterative version for large n.

Secure login: password_hash, password_verify and sessions Medium

Never store plain or MD5/SHA1 passwords; password_hash uses a slow, salted algorithm and stores the algorithm and cost inside the hash, so password_verify needs nothing else. Regenerate the session id after login, set secure cookie flags, and return the same error for "unknown email" and "wrong password" so attackers can't enumerate accounts. Add rate limiting on failed attempts.

Prevent XSS (output escaping) and CSRF (token) in a form Medium

Rule of thumb: validate input, escape output, in the context where it is used. htmlspecialchars with ENT_QUOTES makes user text safe inside HTML and attribute values; JSON for JavaScript needs json_encode, and SQL needs prepared statements (not escaping). The CSRF token proves the POST came from your own form; SameSite cookies add a second layer. Frameworks such as Laravel do both automatically (Blade {{ }} and @csrf).

Secure file upload ($_FILES, size and real MIME type checks) Medium

The form needs enctype="multipart/form-data". Check the error code, the size (also capped by upload_max_filesize and post_max_size in php.ini), and the MIME type detected from the file's content with finfo; the browser-supplied type and extension can be faked. Generate a random name and store files outside the public folder (serve them through a script that checks permissions), so an uploaded .php file can never be executed.

Traits, abstract classes, interfaces, and static vs self (late static binding) Medium

A trait copies methods and properties into a class (horizontal reuse, since PHP has single inheritance); an interface is a contract with no state; an abstract class shares code and forces subclasses to implement abstract methods. self refers to the class where the code is written, while static refers to the class that was actually called, which is what makes factory methods like create() work in subclasses.

Custom exceptions, multiple catch, finally Easy

Since PHP 7, fatal problems like calling a method on null throw Error; both Error and Exception implement Throwable, so catch Throwable at the top level. Since PHP 8, throw is an expression, so it works after ?:, ?? and in arrow functions. Map domain exceptions to HTTP status codes in one place and log the real error without leaking it.

Read a huge CSV with a generator (constant memory) Medium

A function containing yield returns a Generator that produces values lazily, so a 2 GB file is processed with a few kilobytes of memory, whereas file() or reading everything into an array would exhaust memory_limit. Generators compose like Java streams (read, then batch, then insert). yield from delegates to another generator.

Namespaces and PSR-4 autoloading with Composer Easy

PSR-4 maps a namespace prefix to a folder: App\Service\PatientService is loaded from src/Service/PatientService.php, so you never write require for your own classes. One class per file, file name equals class name. use imports a name, and built-in classes need a leading backslash or a use statement inside a namespace. Commit composer.lock so every environment installs the same versions.

Array tasks: unique values, second largest, sort associative arrays by a field Easy

Know which sort functions keep keys: sort/rsort/usort reindex, while asort/arsort/uasort and ksort/krsort preserve the key association. The spaceship operator <=> compares arrays element by element, which gives a neat multi-field comparator. array_unique keeps the original keys, hence array_values. Sorting is O(n log n), and since PHP 8 sorting is stable.

Call an external REST API with cURL (timeouts and error handling) Medium

Always set connect and total timeouts (the default can wait forever), check both transport errors (curl_exec returns false) and HTTP status codes, and decode JSON with JSON_THROW_ON_ERROR so bad responses fail loudly. Named arguments (PHP 8) such as token: let you skip optional parameters. In larger projects, Guzzle or Symfony HttpClient add retries, middleware and PSR-7 messages.

"Tell me about yourself": a 90-second structure Easy

Every item you mention is an invitation for follow-up questions, so mention only what you can explain in detail (architecture, why you chose something, what went wrong). Practise it out loud until it sounds natural, not memorised, and end with a hook such as a project the interviewer will want to ask about.

Answer behavioural questions with STAR (example: "a difficult bug you fixed") Easy

Say "I", not "we", for your own actions, and keep each story to about two minutes. For "a mistake you made", choose a real but recoverable one and spend most of the time on what you changed afterwards (tests, reviews, monitoring). Interviewers are checking ownership, communication and learning, not perfection.

How to approach any system design question (a 45-minute framework) Medium

Drive the conversation: clarify before drawing, state assumptions, and explain every choice as a trade-off ("I'd use a cache here, which adds staleness, so I'd set a short TTL and evict on update"). Start simple (one service, one database) and scale only where the numbers require it. Interviewers value reasoning over buzzwords.

Design a URL shortener (the classic warm-up) Medium

The key discussion points are how you generate unique short codes without collisions at scale, why the read path is cached, and 301 vs 302. Mention that writes and analytics are separated so a burst of clicks never slows down redirects.

How would you scale a Spring Boot + Angular + MySQL application? Medium

Always start with "measure first": find the real bottleneck with metrics and profiling before adding infrastructure. Most applications are limited by the database, so query and index work usually gives the biggest win, followed by caching and moving slow work off the request path.

Design a rate limiter for an API Medium

Name the algorithm, explain its trade-off, and show where the counter lives once there is more than one instance (shared store with atomic operations). Mention it protects against abuse and also protects downstream services, and that the client should back off using Retry-After.

"Production is down. What do you do?" (incident handling) Easy

The key message is "restore service first, find root cause second": a rollback in five minutes beats a perfect fix in two hours. Show calm communication and ownership, and finish with what you would change so the same incident cannot happen again.

Disagreeing with a teammate or lead, and questions to ask at the end Easy

Always have two or three questions ready; "no questions" can come across as low interest. For salary and notice-period questions in HR rounds, give a researched range, be honest about your notice period, and stay flexible on joining logistics.
